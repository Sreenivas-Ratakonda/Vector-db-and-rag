Embeddings: meaning → numbers VECTOR DB

An embedding model turns text into a fixed-length list of numbers, a vector.

"I want my money back" → [0.12, -0.48, 0.33, 0.05, … 384 numbers]

"What is the refund policy?" → [0.10, -0.45, 0.31, 0.07, …] ← very similar

"How many leave days do I get?" → [-0.62, 0.21, -0.05, …] ← very different

Real models: 384 (MiniLM, used in our demo) to 3072 dimensions.

Think: GPS coordinates for meaning

Measuring "close": cosine similarity

MetricIdea
CosineAngle between arrows · 1 = same meaning · default for text
Dot productAngle × length (same as cosine when normalised)
EuclideanStraight-line distance · 0 = same

So what is a vector database?

A database that stores vectors and answers one question very fast:
"Give me the k items most similar to this."

One record

id:       refund-policy.md#2
vector:   [0.10, -0.45, 0.31, … 384]
document: "Refunds go back to the original
           payment method within 5-7 days…"
metadata: {source: refund-policy.md,
           dept: support, year: 2026}

"money back"

🔢 embed

🗄️ k-NN search

Our step 2 demo

IVF (clusters)

Group vectors into neighbourhoods. Search only the nearest few.

Fast, low memory

~95–99% recall

HNSW (graph) ⭐ default

Highways → main roads → local streets. Hop toward the target, drop a level.

Very fast, high recall

Chroma, Qdrant, pgvector, Milvus…

ANN = Approximate Nearest Neighbour: trade a tiny bit of accuracy for huge speed. PQ compresses vectors 10–60× for billion-scale.

Types of vector databases

📦 Libraries

FAISS, hnswlib, Annoy

Fastest, no server. You build persistence and CRUD yourself.

💻 Embedded

Chroma, LanceDB

pip install, runs in-process. Prototypes and small apps. Our demo.

🖧 Self-hosted

Qdrant, Milvus, Weaviate

Full features, scale-out, open source. You operate it.

☁️ Managed

Pinecone, Zilliz Cloud

Zero ops, autoscaling. Cost; data leaves your infra.

🧩 Extensions

pgvector, Elasticsearch, MongoDB Atlas, Redis

Vectors inside the DB you already run.

Rule of thumb

Already on Postgres → pgvector · Learning / prototype → Chroma · Billions of vectors, multi-tenant → Qdrant / Milvus / Pinecone · Keyword + vector → Elastic / Weaviate / Qdrant

Beyond RAG: semantic search · recommendations · image search · dedup · anomaly detection · agent memory

Why LLMs need help RAG

  • 🗓️ Knowledge cutoff: doesn't know last week's changes
  • 🔒 No private data: never saw your HR policy
  • 🤥 Hallucination: confidently invents "14-day refunds"
  • 📏 Limited context: can't paste 50,000 pages each time
  • 🔍 No citations: can't verify the answer

📕 Plain LLM = closed-book exam

Smart, answers from memory, sometimes bluffs

📖 RAG = open-book exam

Looks up the right pages of your book first, then answers

Takeaways

1 · Embeddings

turn meaning into numbers. Close numbers = similar meaning.

2 · Vector DBs

find the most similar vectors fast (HNSW), with persistence and filters.

3 · RAG

retrieve → augment → generate: LLM answers from your data, with citations.

4 · Not always a vector DB

Small → prompt / in-memory. Structured → SQL. Codes → keyword. Big → vector DB.
